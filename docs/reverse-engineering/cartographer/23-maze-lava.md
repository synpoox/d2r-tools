## 23. The maze builder's case for LevelType 28 (Lava, River of Flame, issue #239)

Build: D2R 3.3 build 93847, D2RLoader 1.3.1-beta, image stamp `0x6ab3782c`. Addresses are RVAs in the memory-layout dump. All of it is static (the dump read with
`plugins/cartographer/tools/dump_dis.py`); nothing here was run in game. No new hook or signature: the maze hooks of section 5 are reused.

Consequences for the table row `{"Lava", 28, "MazeLava", "Cartographer Lava", 24, 836, {0,0,0,0}, false}`:

## Edge fill (issue #372)

The Lava case only walks, so no room exists beyond the plan's outer rooms, and a Lava piece's lava fringe is a few tiles deep: from ground near the outer wall the rest of the screen was black. The plan now adds a ring of filler rooms (`ringCells` of the tileset row, 1 for Lava, 0 for Cave, Crypt and Ice) on every free cell within one cell (8 ways) of a plan room and inside the level box. Each is made with add-room `0x3e77a0` from an adjacent room, which also makes the link to its parent, and picked with `0x3eb960`, which therefore gives 836 plus the mask of that back link: a walkable dead end, not the closed cell. After the pick the room's piece id (`piece+0`) is set to 836, the closed cell, so the filler has no exits and no ground to populate. No new address and no new table.

Seen in game (slot 7, Large Lava, build 1.3.1-beta): with the first version (fillers kept 836 plus the back-link mask) the log read "maze filler ring: N of N rooms made" and "built as planned", and the bottom, top and left outer rooms and a corner showed lava and cliff to the screen edge. With the piece id write the log reads "54 of 54 rooms made, 54 set to the closed piece 836", the build is still "as planned", arrival is still in the entrance cell, and the same edges show no black field. `cheat goto` onto two filler cells left the player at the arrival (no walkable ground there). Timing (static, from review): the picker `0x3eb960` writes the piece id, file -1 and the Fixed bit at `0x3ebba4..0x3ebbc3`, and the file is drawn at room load, so setting the id after the pick is read by the load. Later check (docs/cartographer/checks/2026-11-13-lava-edges-check.md): Large and ExtraLarge layouts and a clipped one (east, north, south) show no black field at the edges. Not seen: a per-room monster or unique count for the fillers (only that they have no walkable ground), the west edge of a layout that was clipped (the in-game check of seed 5826635208936150018 looked at all four edges of its refit layout, which is whole, so it did not see a clipped west edge).

A layout that does not fit with a one-cell margin is planned at the largest level (360 x 360, still inside the automap int16 range) with margin 0 and the ring is clipped to the level, so a layout that touches the level's edge can still have a bare side. Issue #421: the first room has to be a used cell and the game centres it, so a layout 13 rooms across (the most a 15-room level holds with a ring) has one cell that can be the first room on each axis, usually an unused one; over 2000 seeds per shape, ExtraLarge layouts clipped before: Corridor 294 of 1415, Winding 360 of 1807, Branching 122, Loop 45, Sprawl 190, Open 0 (1011 of 11186 in all); Large: Corridor 126 of 1989, Winding 12, the other four 0 (138 of 11989 in all). The root-cell assumption was not wrong (capacityAt matches the game's centred first room), the choice was too narrow. `planForSeed` now tries the next refit layouts (the same refit seeds a layout that does not fit uses, up to 8) while the plan reports `ringClipped`, and keeps the first clipped plan only if none has a whole ring: 0 clipped after in every shape and both sizes, over the same seeds (test `Lava: a layout that fits with a one-cell ring is not clipped`). A seed whose first layout was clipped therefore builds a different layout than before. The level stays 360 x 360 at most. The arrival box check counts the filler cells (`planCellRoom`); a refused filler is logged as a warning and leaves the arrival, event and boss to the game.
